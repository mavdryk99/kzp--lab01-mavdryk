# Звіт до лабораторної роботи № 2

## 1. Тема, номер і варіант
- Предметна область: готель
- Номер варіанта: 14
- Операційна система: Windows 11

## 2. Мета роботи
Перебудувати предметну частину програми: замінити рядкові записи й паралельні змінні
класом-сутністю з інкапсульованим станом, додати перевірку в конструкторі,
статичний фабричний метод fromCsv та record для підсумкових показників.

## 3. Стан до і після цієї роботи

| | До | Після |
|---|---|---|
| Один запис | рядок і поля `fields[i]` | об'єкт класу `Booking` |
| Перевірка | умови в циклі в `main` | конструктор і `fromCsv` |
| Набір даних | змінні-лічильники в `main` | `List<Booking>` |
| Підсумок | окремі змінні | record `BookingSummary` |
| Обчислення | у циклі разом із читанням | окремий метод `summarize` |

## 4. Клас-сутність
Клас `Booking` має приватні незмінні поля: `room`, `guest`, `nights`, `nightlyRate`, `category`.
Конструктор перевіряє: ім'я гостя і категорія не null і не порожні; номер кімнати
та кількість ночей не від'ємні; тариф не від'ємний і скінченний. Якщо перевірка
не пройдена, кидається `IllegalArgumentException`, і об'єкт не створюється.
Для кожного поля є геттер, сеттерів немає. `toString` форматує дробові числа
через `Locale.ROOT`.

## 5. Фабричний метод і record
`Booking.fromCsv(String line)` розділяє рядок за `;`, перевіряє, що полів рівно 5,
перетворює числа і створює об'єкт. Нечислове поле дає `IllegalArgumentException`
з повідомленням про формат. У циклі читання виняток перехоплюється, і до повідомлення
додається номер рядка.

Record `BookingSummary(count, totalNights, totalRevenue, longestStay)` зберігає
незмінні підсумкові показники; компактний конструктор перевіряє їх допустимість.

## 11. Відповіді на контрольні питання
1. Об'єднує пов'язані дані й логіку в один об'єкт, запобігаючи розсинхронізації та некоректному стану.
2. private обмежує доступ усередині класу; final забороняє зміну значення після ініціалізації.
3. Приховування внутрішнього стану й логіки об'єкта. Запобігає неконтрольованій зміні даних ззовні.
4. Щоб унеможливити створення об'єкта в некоректному (невалідному) стані.
5. Objects.requireNonNull перевіряє на null; isBlank() перевіряє, чи рядок порожній або з одних пробілів.
6. Забезпечує незмінність (immutability), унеможливлюючи псування даних об'єкта після створення.
7. Поля private final, канонічний конструктор, гетери з назвами полів, перевизначені equals(), hashCode(), toString().
8. record — лаконічний незмінний носій даних з автоматично згенерованим шаблонним кодом.
9. Бо final фіксує лише посилання на список, але не захищає елементи всередині змінного списку.
10. Для парсингу рядка CSV та перетворення його на готовий об'єкт.
11. Усередині циклу обробки файлу, щоб помилка в одному рядку не зупиняла зчитування всього файлу.
12. Щоб уникнути забруднення списку некоректними даними й зберегти його цілісність.
13. toString призначений для відлагодження людиною (у логах), а CSV — для автоматичного обміну даними.
14. Гарантує однаковий формат чисел і дат (наприклад, крапка в дробах) незалежно від мовних налаштувань ОС.
15. Arrange (підготовка) -> Act (виконання) -> Assert (перевірка результату).
16. Передачу null, порожніх рядків (blank), від'ємних чи недопустимих чисел.
17. Успішним проходженням усіх раніше написаних модульних тестів.
18. Це гарантує відсутність регресії — нові зміни не зламали створену раніше функціональність.
19. pom.xml, .gitignore, конфігурації CI/CD (.github/workflows), Maven Wrapper (mvnw, mvnw.cmd).
20. private final String name; — приховує внутрішній стан класу та захищає його від змін ззовні.
